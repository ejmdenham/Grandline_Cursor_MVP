### 3. Architecture / Infrastructure

**What is there**

- **Terraform** in [infra/terraform/](infra/terraform/): AWS (e.g. `eu-north-1`), no remote backend by default.
- **Cognito**: user pool, app client, hosted UI domain — used for sign up, sign in, and session (no REST auth endpoints; app talks to Cognito directly).
- **API Gateway**: HTTP API; base URL is an output.
- **Lambda**: Races API in [infra/lambda/races/](infra/lambda/races/) — `GET /races?inviteCode=...` and `GET /races/{id}`; Cognito JWT required.
- **DynamoDB**: Races table (id, name, checkpoints, amot, start_window, invite_code, paid, etc.) with GSI `by-invite-code` for join flow.
- **Outputs**: Cognito IDs, API base URL, races table name (used by [scripts/gen-env.sh](scripts/gen-env.sh) for mobile `.env`).

**What it does**

- Auth: user identity and sessions via Cognito.
- Races: fetch race by invite code or by id for the player app (join flow and race details).

**What is to come (later phases)**

- **Phase 3+**: Same API and tables support join flow and pre-race; no new infra called out in Phase 3.
- **Phase 4–5**: In-race and leaderboard may need additional Lambdas or table/GSI (e.g. race results, leaderboard reads); keep description concise.
- **Phase 6**: Beta Pass / paid-race gating (backend support as needed).
- **Phase 7 (Beyond MVP)**: Organizer flow (create race, form, API); teams (data model and API); payments (entry fees, prize pool); optional S3 for assets. Reference Concept: “Race Setup”, “Team Dynamics”, “Financial Transactions”.

Keep the “to come” list short: a few bullets per phase band (3–5, 6, 7) so infra stays “what exists + what’s planned” without full implementation detail.

### 4. App (mobile player)

**What is there**

- **Stack**: React Native (Expo) in [apps/mobile/](apps/mobile/).
- **Auth**: [apps/mobile/src/services/auth.ts](apps/mobile/src/services/auth.ts) (Cognito), [AuthContext](apps/mobile/src/contexts/AuthContext.tsx), [Auth stack](apps/mobile/src/navigation/AuthStack.tsx) (sign in, sign up, confirm).
- **Navigation**: [RootNavigator](apps/mobile/src/navigation/RootNavigator.tsx) (auth gate), [MainDrawer](apps/mobile/src/navigation/MainDrawer.tsx) (drawer with map as home), placeholder screens (Profile, Join Race, Leaderboard, Rules).
- **Map**: [MapScreen](apps/mobile/src/screens/MapScreen.tsx) as default home (full-screen map, north-up, pan/zoom).
- **Config**: [apps/mobile/src/config/env.ts](apps/mobile/src/config/env.ts) (Expo env from `.env`), [assets.ts](apps/mobile/src/config/assets.ts); `.env` generated by [scripts/gen-env.sh](scripts/gen-env.sh) from Terraform outputs.

**What it does**

- User can sign up, sign in, and see the map as home; drawer opens for placeholders (no race-specific UI yet).

**What is to come (later phases)**

- **Phase 3**: Join race by invite code, pre-race bottom sheet (description, AMOT, start countdown, “Start Race”), checkpoints/finish on map, top overlay (race name, time, progress).
- **Phase 4**: In-race: GPS, player marker, checkpoint detection, HUD, in-race bottom sheet (distance to next, “Center Map”).
- **Phase 5**: Post-race bottom sheet and leaderboard screen.
- **Phase 6**: Full drawer content (Profile, active race, Rules/Safety), Beta Pass gating for paid races, waiver (optional), asset pipeline and polish.
- **Phase 7**: Teams, social (friends, chat), live opponents/trails (Concept); organizer flow is a separate app/web.

Again, keep “to come” to a few bullets per phase so the README stays a map, not a spec.
