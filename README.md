# Grandline

Grandline is a real-time adventure and racing app that brings competitive exploration to the real world. Designed for thrill-seekers, athletes, and adventurers, it lets users form teams and take part in races with specific checkpoints and allowed means of transport (AMOT)—running, biking, or boating. The player app is map-first: the map is the home screen, with real-time location and progress front and center.

Grandline is more than a racing app—it’s an adventure platform that combines competition with exploration. By tying real-world challenges to the app, it encourages outdoor activity, teamwork, and strategic thinking, whether you’re racing to the finish or exploring new terrain.

## Architecture / Infrastructure

### What is there

- **Terraform** ([infra/terraform/](infra/terraform/)): AWS in `eu-north-1`, no remote backend by default.
- **Cognito**: User pool, app client, hosted UI domain. Used for sign up, sign in, and session; the app talks to Cognito directly (no REST auth endpoints).
- **API Gateway**: HTTP API; base URL is a Terraform output.
- **Lambda**: Races API in [infra/lambda/races/](infra/lambda/races/) — `GET /races?inviteCode=...` and `GET /races/{id}`; requires Cognito JWT.
- **DynamoDB**: Races table (id, name, checkpoints, amot, start_window, invite_code, paid, etc.) with GSI `by-invite-code` for the join flow.
- **Outputs**: Cognito IDs, API base URL, races table name — used by [scripts/gen-env.sh](scripts/gen-env.sh) to generate the mobile app’s `.env`.

### What it does

- **Auth**: User identity and sessions via Cognito.
- **Races**: Fetch a race by invite code or by id for the player app (join flow and race details).

### What is to come (later phases)

- **Phase 3+**: Existing API and tables support join flow and pre-race; no new infra called out in Phase 3.
- **Phase 4–5**: In-race and leaderboard may need extra Lambdas or table/GSI (e.g. race results, leaderboard reads).
- **Phase 6**: Beta Pass / paid-race gating (backend support as needed).
- **Phase 7 (Beyond MVP)**: Organizer flow (create race, form, API); teams (data model and API); payments (entry fees, prize pool); optional S3 for assets. See Concept: “Race Setup”, “Team Dynamics”, “Financial Transactions”.

## App (mobile player)

### What is there

- **Stack**: React Native (Expo) in [apps/mobile/](apps/mobile/).
- **Auth**: [auth.ts](apps/mobile/src/services/auth.ts) (Cognito), [AuthContext](apps/mobile/src/contexts/AuthContext.tsx), [Auth stack](apps/mobile/src/navigation/AuthStack.tsx) (sign in, sign up, confirm).
- **Navigation**: [RootNavigator](apps/mobile/src/navigation/RootNavigator.tsx) (auth gate), [MainDrawer](apps/mobile/src/navigation/MainDrawer.tsx) (drawer with map as home), placeholder screens (Profile, Join Race, Leaderboard, Rules).
- **Map**: [MapScreen](apps/mobile/src/screens/MapScreen.tsx) as default home (full-screen map, north-up, pan/zoom).
- **Config**: [env.ts](apps/mobile/src/config/env.ts) (Expo env from `.env`), [assets.ts](apps/mobile/src/config/assets.ts); `.env` generated by [scripts/gen-env.sh](scripts/gen-env.sh) from Terraform outputs.

### What it does

Users can sign up, sign in, and see the map as home; the drawer opens with placeholder items (no race-specific UI yet).

### What is to come (later phases)

- **Phase 3**: Join race by invite code; pre-race bottom sheet (description, AMOT, start countdown, “Start Race”); checkpoints/finish on map; top overlay (race name, time, progress).
- **Phase 4**: In-race: GPS, player marker, checkpoint detection, HUD, in-race bottom sheet (distance to next, “Center Map”).
- **Phase 5**: Post-race bottom sheet and leaderboard screen.
- **Phase 6**: Full drawer content (Profile, active race, Rules/Safety); Beta Pass gating for paid races; optional waiver; asset pipeline and polish.
- **Phase 7**: Teams; social (friends, chat); live opponents/trails (Concept); organizer flow as a separate app or web.

## Quick start

**Backend:** From repo root, `cd infra/terraform`, copy `terraform.tfvars.example` to `terraform.tfvars`, run `terraform apply`, and note the outputs.

**Mobile:** Run `./scripts/gen-env.sh` (from repo root, with Terraform outputs available) to write `apps/mobile/.env`. Then `cd apps/mobile && npx expo start` (and run iOS/Android as needed).

**Monorepo:** Always run Expo from `apps/mobile`. The root holds workspaces and version pinning for native modules (e.g. gesture-handler, reanimated).
